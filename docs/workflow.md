# 开发工作流

本项目仅交付微信原生小程序，当前为本机演示阶段。先确认任务所处阶段，再按下表修改。

| 场景 | 先读 | 修改位置 | 完成条件 |
| --- | --- | --- | --- |
| 页面与交互 | `client-contract.md`、开发计划第一阶段 | `miniprogram/pages/` 与公共样式 | loading、空态、失败态明确；不绕过 repository；静态检查通过 |
| 数据服务与检索 | `client-contract.md`、`../HARNESS.md` | `miniprogram/services/`、必要工具函数 | 所属人隔离、原件关联和日期规则行为测试通过 |
| 微信登录与家庭共享 | 开发计划第二阶段 | 云端适配、服务端、契约与部署配置 | 服务端验证成员权限；并发修改和跨家庭拒绝有测试；真机双账号验证 |
| 云端识别 | 开发计划第三阶段 | 服务端识别适配、核对页 | 不在小程序存密钥；保留原件；失败和重试可见；不自动确认医疗字段 |
| 发布与验收 | 开发计划第四阶段、`../README.md` | 配置、说明及必要修复 | 微信真机主流程通过；明确真实服务和演示区别 |

## 检查顺序

```sh
bash scripts/check-redlines.sh
npm run check
npm test
```

新增业务服务方法先更新契约，再修改实现和调用方。相机、文件预览等微信能力需要开发者工具或真机验证；Node 检查不能证明设备能力正常。

修改红线脚本时，临时构造能触发对应规则的违规探针，确认命令失败，删除探针后确认恢复通过。探针不可混入提交。Git 操作遵循 [提交规范](git-commit-conventions.md)。
