# 家庭健康档案微信小程序

面向家人共同维护的健康档案：病历、检查报告和处方拍照归档，保留原件，按所属人和就诊经过整理，记录实际用药日期与备注。只开发微信原生小程序，不包含 H5。

## 当前交付

这是第一阶段的本机演示开发骨架。页面与数据服务已经分层，默认在本机保存演示数据及用户选择的演示文件。

- 首页：多档案切换、近期／季度／年度概览。
- 档案：关键词、症状、诊断、检查、药品及年月／季节筛选。
- 上传：照片或 PDF、多页资料、明确标识的模拟识别、核对、关联或新建就诊、先保存后关联。
- 详情：原件回看、同一报告在复诊中引用、每种处方药分别记录实际开始／停止日期和备注。
- 档案管理：头像、名称、出生日期；家庭共享和云端识别的已确认设计。

**当前没有真实微信登录、跨设备家庭同步、云端原件存储或真实 AI 识别。模拟识别不会读取照片文字。** 云服务未配置或调用失败时不会假装保存成功。种子样例没有原件，查看时会明确提示；自行添加的演示文件才可回看。

## 本地预览

1. 使用微信开发者工具导入本目录，项目配置已指向 `miniprogram/`。
2. 确认 `project.config.json` 中的 `appid` 是自己的小程序 AppID。AppSecret 不写入客户端。
3. 保持 `miniprogram/config.js` 中 `mode: 'demo'`，即可预览本机流程。此阶段无需安装 npm 依赖。
4. 在工具和真机中验证拍照、文件选择及图片／PDF 预览；游客模式对部分能力有限制。

演示资料只在当前设备保存，不会同步给家人。请使用测试或脱敏材料；真实长期保存应等待云端接入。开发者工具清理缓存会影响本机演示数据。

## 验证

需要 Node.js 16.20 或更高版本：

```sh
npm test
npm run check
```

测试覆盖所属人隔离、资料引用去重、否定原文、原件保留、归档关联、并发版本和用药日期校验。静态检查不代替微信开发者工具和真机验证。

## 后续开发

按 [开发计划](docs/development-plan.md) 依次接入：微信身份与家庭邀请、服务端权限及原件存储、云端识别任务、真机联调和发布。

云适配入口在 `miniprogram/services/cloud.js`，当前只约定调用名 `healthApi`，尚无服务端实现；不要仅切换模式就当作云服务已经部署。真实服务必须验证家庭成员权限，不能依赖本机的所属人筛选。
